A 2 second sprite into a small pool guarantees exhaustion. Every play returns ((gen << 8) | ch) >>> 0: the channel it landed on, stamped with that channel's generation counter.

Fill the pool, then press stop on a stolen row. The channel keeps playing: the generation moved on, so the old handle addresses a voice that no longer exists.

handles issuednewest first

LIVE = gen matches and the voice is still sounding. STOLEN = the channel was recycled under it. ENDED = it played out. Calling stop() on anything but LIVE is a guarded no-op, never a mis-fire.

Sustained fire at 600/s means 600 AudioBufferSourceNodes per second. Sources are one-shot by spec, so that allocation is unavoidable. What the pool avoids is the rest: gains and panners are built once at construction, and channel state lives in Float64Array / Uint32Array slots that never grow.
